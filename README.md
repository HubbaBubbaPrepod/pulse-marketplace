# Pulse Marketplace

[![CI](https://github.com/HubbaBubbaPrepod/pulse-marketplace/actions/workflows/ci.yml/badge.svg)](https://github.com/HubbaBubbaPrepod/pulse-marketplace/actions/workflows/ci.yml)

[English](README.en.md) · MIT

Каталог расширений для self-hosted Pulse: GitHub → обнаружение релиза → проверка конкретного пакета → решение модератора → скачивание JSON. Модули исполняются агентом на сервере пользователя; marketplace их не запускает.

Next.js 16.4 / React 19.3 + Nest.js 12 + PostgreSQL 18 в Turborepo. Интерфейс поддерживает русский и английский языки, светлую и тёмную темы, GSAP и reduced motion.

## Что работает

- Вход по email/паролю, сессии в PostgreSQL, выход, роли автора/модератора/администратора, защита приватных API и CSRF.
- GitHub OAuth с PKCE и Google OIDC; подключение GitHub к существующему аккаунту выполняется отдельным подтверждённым действием. Совпадение email не объединяет аккаунты.
- Подтверждение email и сброс пароля: одноразовые ссылки, постоянная очередь писем, отзыв предыдущих сессий после смены пароля. Способы входа и отправка писем отключены, пока не настроены провайдеры/SMTP.
- Обнаружение публичных репозиториев по topic `pulse-module`, постоянная очередь проверок, учёт ограничений GitHub, повторная проверка владельца по numeric ID.
- Проверка маркера и установочного JSON, размеров, платформ, SHA-256 и заголовков ELF/PE. Пакет сохраняется до модерации; загрузка отдаёт сохранённые байты по хешу.
- Каталог содержит только одобренные версии. Решение и аудит записываются одной транзакцией. Модератор не может одобрять свои модули; администратор может одобрять через обычный вход, включая собственные модули, с обязательными проверками и аудитом; при изменении источника создаётся новая ожидающая версия. Отозванная версия недоступна для скачивания, если её байты не опубликованы в другой одобренной версии.
- Кабинеты подключены к API; очередь модерации имеет фильтры статусов и пагинацию. Примеры не публикуются и не подставляются при ошибке API.

## Локальный запуск

Нужны Node.js 24 LTS, npm и работающий Docker Desktop.

```sh
npm ci
node scripts/setup-local-env.mjs
docker compose --env-file .env -f deployment/compose.yml up -d --wait
npm run migrate --workspace @pulse-marketplace/api
node --env-file=.env scripts/bootstrap-admin.mjs admin@example.com
npm run dev
```

Открыть [http://127.0.0.1:3100/ru/](http://127.0.0.1:3100/ru/) или `/en/`. В разработке `localhost` перенаправляется на `127.0.0.1`, чтобы Origin и cookie совпадали. API слушает только `127.0.0.1:3101`; Next проксирует `/api/v1/`. PostgreSQL доступен только на `127.0.0.1:54329`.

Команда bootstrap создаёт **нового** администратора и сохраняет случайный пароль в игнорируемый файл `artifacts/admin-access.txt`. Существующие аккаунты и файлы не перезаписываются. Пароль не выводится в терминал. Не публикуйте этот файл и `.env`.

Аккаунты, сессии, аудит и очередь живут в постоянном Docker-томе `pulse-marketplace_marketplace_database`. Перезапуск процессов или контейнера их не удаляет. Снимки пакетов находятся в `data/packages/`; это отдельная обязательная часть резервной копии. Удаление тома (`down -v`) уничтожает базу.

Настройки и ограничения: [docs/backend.md](docs/backend.md). Шаблон без секретов: [.env.example](.env.example).

## Проверки

```sh
npm test
npm run lint
npm run format:check
npm run build
npm run verify:production
```

Тесты API требуют запущенного PostgreSQL и `.env`. Они создают отдельные временные схемы и удаляют только их; основную базу не очищают. Turbo не кеширует тесты с базой. `lint` запускает ESLint для web и TypeScript для API/контрактов. Проверка production временно запускает собственный Next-процесс на свободном loopback-порту, проверяет каталог/редиректы/защиту кабинетов и завершает только этот процесс; API должен быть запущен отдельно.

## Границы текущего этапа

GitHub OAuth проверен в локальной установке; для вашей установки настройте собственное приложение. Google OAuth и SMTP требуют отдельных реквизитов; их живой вход и доставка пока не проверены. Почта может оставаться отключённой. Пока поддерживается публикация из персональных GitHub-репозиториев: версии организаций получают ошибку проверки до реализации проверки авторства внутри организации. Одобрение не является гарантией безопасности нативного кода.

В Pulse Monitor реализован добровольно подключаемый каталог с поиском, выбором версии и установкой проверенного JSON. Ручной импорт сохранён. Реальная установка Docker v1.0.3 проверена через локальный marketplace; обновления установленного ID выполняются вручную.

Публичная установка работает через Nginx и HTTPS, со службами systemd, ограничением запросов и ежедневными резервными копиями. [Эксплуатация и восстановление](docs/production.md). Монитор, агент, Docker-модуль и лендинг остаются отдельными репозиториями. Агенты к marketplace не обращаются; метрики и журналы сюда не передаются.

## Структура

- `apps/web/` — Next.js, RU/EN, каталог и защищённые кабинеты.
- `apps/api/` — Nest.js, SQL-миграции и интеграционные тесты.
- `packages/contracts/` — общие типы API.
- `deployment/compose.yml` — локальный PostgreSQL с постоянным томом.
- `docs/marketplace-design.md` — утверждённая архитектура доверия.
- `docs/backend-bootstrap.md` — выполненные работы, решения и ограничения проверки.
- `docs/frontend-requirements.md` — требования к интерфейсу и motion.

Изображения модулей — иллюстрации интерфейса, не официальные логотипы и не признак участия соответствующих проектов.
