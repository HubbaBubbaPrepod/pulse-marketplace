# Темы Pulse Marketplace

[English](THEMES.en.md)

Каталог: https://marketplace.hubba-cloud.ru/ru/themes/. Читать каталог и скачивать одобренные темы можно без входа. Предпросмотр использует вымышленные показания; серверы пользователя не подключаются. Встроенные темы в верхнем блоке — примеры оформления из Monitor, а не публикации сообщества.

## Установка

Откройте тему, выберите опубликованную версию и нажмите «Скачать тему». В Monitor откройте «Настройки → Внешний вид → Импортировать тему» и выберите JSON. Файл содержит прежний ThemeDefinition schemaVersion1; обновление агента не требуется. Импорт добавляет локальную копию: последующие изменения автора автоматически не применяются.

## Публикация

1. Создайте публичный GitHub-репозиторий и добавьте topic `pulse-theme`.
2. Скопируйте [маркер](../examples/theme/pulse-marketplace.json) и [пример пакета](../examples/theme/theme.json). Файл `pulse-marketplace.json` разместите в корне. `moduleId` — техническое поле общего обнаружения; для темы это её ID. `kind` должен быть `theme`.
3. В редакторе Monitor экспортируйте своё оформление и поместите объект в поле `theme` пакета. Внешний ID и `theme.id` должны совпадать. Укажите собственные имя, описание и версию.
4. Создайте тег `v1.0.0` (номер совпадает с `version`) и опубликованный GitHub Release. Прикрепите `theme.json` отдельным asset. Маркер должен присутствовать в commit тега. Предварительные версии тоже проходят модерацию.
5. Планировщик проверяет репозитории каждые30минут с учётом лимитов GitHub. В кабинете автора можно отправить репозиторий на обнаружение. После автоматической проверки версия ожидает отдельного решения модератора. До одобрения её нет в публичном каталоге и скачать её нельзя.

Каждая новая версия/изменение исходных байтов требует отдельной проверки. Нельзя заменить уже одобренный пакет другими байтами под тем же owner/ID/version — выпустите новую версию. ID и версии используют общее пространство публикаций с модулями: выбирайте отдельный ID для темы. Сохранённые публикации не удаляются автоматически при исчезновении GitHub-репозитория.

## Формат и безопасность

Пакет: `schemaVersion`, `kind`, `id`, `name`, `version`, `description`, `theme`; пример в репозитории является документацией и не означает одобрения публикации. Ограничение пакета64КиБ. Оформление содержит все12 цветов Monitor в формате `#RRGGBB`, режим `dark`/`light`, скругление0–24, необязательный акцент и ограниченные настройки шрифтов. Разрешены только встроенные семейства шрифтов. Неизвестные поля, повторяющиеся JSON-ключи, CSS, HTML, JS, бинарники и ссылки на внешние ресурсы отклоняются. Предпросмотр применяет значения только внутри макета, не ко всему Marketplace.

Исходный пакет сохраняется с SHA-256. Скачивание возвращает вложенный объект `theme` с каноническим порядком ключей, а не оболочку релиза; у него другой SHA-256, указанный как `themeSha256` и заголовок `X-Content-SHA256`. Хэш исходного пакета отображается отдельно. При скачивании повторно проверяются одобрение, целостность исходного snapshot и формат. Отзыв публикации закрывает скачивание.

## API

- `GET /api/v1/themes?query=&mode=dark|light&cursor=` — последние одобренные версии,30записей и `nextCursor`. Отсутствие mode означает оба режима.
- `GET /api/v1/themes/:owner/:id` — тема и до100 опубликованных версий.
- `GET /api/v1/themes/:owner/:id/versions/:version/download` — совместимый с Monitor файл оформления.

Прежние `/catalog`, `/modules/...` и `/packages/:hash` возвращают только модули. Агенты не загружают темы. Существующие маркеры без `kind` по-прежнему обозначают модули. Новых сервисов/переменных окружения и миграции схемы БД не требуется: тип хранится в проверенном manifest ревизии.
